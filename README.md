# mrt-plus-site

Публічний сайт мережі діагностичних центрів «МРТ ПЛЮС».
Поточний стан: сторінка стилів, збірка **0.2**. Сторінок сайту ще немає.

## Що всередині

| Шлях | Що це |
|---|---|
| `styleguide.html` | сторінка стилів: усі базові елементи сайту з живими прикладами |
| `index.html` | заглушка кореня з посиланням на сторінку стилів |
| `assets/css/tokens.css` | кольори, шрифти, шкала, відступи – єдине джерело правди |
| `assets/css/base.css` | скидання, текст, розкладка |
| `assets/css/components.css` | компоненти: кнопки, форми, картки, ціни, шапка, підвал |
| `assets/css/styleguide.css` | оформлення самої сторінки стилів, на сайт не йде |
| `assets/js/site.js` | мобільне меню і копіювання токенів; без нього сторінка робоча |
| `assets/img/logo-mark.svg` | знак-заглушка до отримання оригінального логотипа |
| `data/centers.json` | заготовка даних центрів: підтверджене заповнене, решта `null` |
| `docs/styleguide.md` | рішення щодо вигляду і чому вони такі |
| `404.html` | сторінка «такої сторінки немає» |
| `wrangler.jsonc` | конфіг воркера: каталог статичних файлів і обробка 404 |
| `.assetsignore` | що не віддавати у мережу |
| `perevirka.py` | валідатор, запускається перед кожним заливанням |

## Як подивитися

Відкрити `styleguide.html` подвійним кліком. Збірка не потрібна: це звичайний
HTML і CSS без залежностей. Шрифти тягнуться з Google Fonts, без інтернету
сторінка покаже системні – це нормально.

## Перед заливанням

```
python3 perevirka.py
```

Валідатор перевіряє довге тире, невизначені CSS-змінні, биті локальні
посилання, парність тегів і цілісність JSON. Ненульовий код виходу означає:
не заливати.

## Стек

Питання стеку сайту відкрите (Next.js або генератор на Python, як у «Медикал
Плюс»). Сторінка стилів навмисне зроблена стек-нейтральною: `tokens.css`
переноситься в Tailwind через `@theme` без зміни значень, а розмітка компонентів
однаково лягає і в React-компоненти, і в шаблони генератора. Вибір стеку не
блокує роботу над виглядом.

## Деплой

Cloudflare **Workers** зі статичними файлами – так само, як решта проєктів
акаунта. Не Pages: Pages у режимі підтримки, розвиток іде у Workers, і сайту
згодом знадобиться жива логіка (форма зворотного дзвінка, вільні слоти з API),
яка на Workers живе в цьому ж проєкті.

Створення: Workers & Pages → Create → Workers → Import a repository →
`mrt-plus-site`.

| Поле | Значення |
|---|---|
| Build command | порожньо |
| Deploy command | `npx wrangler deploy` |
| Branch | `main` |

Решту читає `wrangler.jsonc`: ім'я воркера, каталог статичних файлів (корінь
репозиторію), сторінка 404. `.assetsignore` тримає поза мережею службові файли –
`README.md`, `perevirka.py`, `docs/`, `data/`, конфіг воркера.

`_headers` віддає `X-Robots-Tag: noindex`, `robots.txt` закриває сайт від
пошуковиків. Обидва знімаються в день запуску, не раніше.

## Номер збірки

Кожна збірка отримує номер, видимий у трьох місцях: у першому екрані сторінки
стилів, у підвалі і в цьому файлі. Номер підвищується при кожній передачі
архіву – по ньому звіряється, що на Pages виїхала саме нова версія.

## Правила, які діють у цьому репозиторії

- Тільки коротке тире (–), ніколи довге.
- Повні назви послуг, без скорочень.
- Адреси сторінок – латиницею, одна схема транслітерації:
  `kyiv`, `zhytomyr`, `rivne`, `lutsk`, `kovel`, `sheptytskyi`.
- Невідомий факт не вигадується: у даних стоїть `null` і рядок у
  `potrebuye_perevirky`.
- Кольори і розміри в розмітці не пишуться – тільки змінні з `tokens.css`.
